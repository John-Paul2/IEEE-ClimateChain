# VeriCEMS Threat Model

> **Document Status:** Working Prototype Assessment (IEEE ClimateChain Hackathon 2026, Track 4)  
> **Honesty & Scope Notice:** This document describes a hackathon prototype. It does **not** claim full production security, nor has it undergone external third-party audit. All evaluations, evidence links, and metrics are derived strictly from reproducible test and benchmark outputs in this repository.

---

## 1. System Overview & Scope

VeriCEMS provides a tamper-evident telemetry and verification pipeline designed for the EU Carbon Border Adjustment Mechanism (CBAM). It addresses the oracle problem of self-reported industrial smokestack emissions data by combining edge cryptographic hashing and signing, off-chain dual physics/ML verification, an optimistic on-chain challenge window backed by staked economic bonds, and browser-verifiable Merkle proofs.

### System Boundaries
- **Edge Layer:** Stack gas analyzers connected to an edge gateway running a cryptographic module (modeled as `SoftwareSecureElement`).
- **Data Transport & Chaining:** Telemetry records signed with ECDSA P-256 and linked into an unbroken SHA-256 hash chain, grouped into batches with Merkle roots.
- **Verification Committee:** 5 independent off-chain verifier nodes running deterministic cryptographic, physics mass-balance, and physics-informed autoencoder (ML) checks.
- **Smart Contract Layer (EVM L2 / Local Anvil):** 6 contracts (`DeviceRegistry`, `BondVault`, `BatchAnchor`, `VerifierQuorum`, `Challenge`, `Attestation`) executing economic enforcement, commit-reveal quorum voting, and challenge arbitration.
- **Consumer Layer:** EU importer portal running browser-side Merkle proof verification and CBAM liability cost calculations.

## 2. Threat Actors

| Actor | Profile & Motivation | Capabilities |
|---|---|---|
| **Malicious Plant Operator / Exporter** | Seeks to underreport CO₂ emissions or Specific Embedded Emissions (SEE) to evade CBAM certificate liabilities (saving €40–€100/tCO₂e [ILLUSTRATIVE EU ETS price range]) or avoid the 10%–30% punitive default markup. | Controls plant network, edge gateway filesystem, stack analyzer maintenance access, and local data historians. May possess operator private keys. |
| **Dishonest / Lazy Verifier Node** | Seeks to collect verification rewards without executing CPU-intensive ML and physics inference, or colludes with plant operator to rubber-stamp fraud. | Holds verifier private key, participates in `VerifierQuorum` voting committee. Cannot alter on-chain smart contract bytecode. |
| **Corrupted Verifier Majority (≥ 3 nodes)** | Cartelized group seeking to extort operators via false fraud flags or censor legitimate batches. | Controls 3-of-5 voting threshold in `VerifierQuorum`. |
| **Network Eavesdropper / MitM** | Seeks to intercept industrial telemetry for corporate espionage or inject forged packets in transit. | Monitors and tampers with unencrypted off-chain network traffic between gateway and verifier nodes. |
| **Hostile Third Party / Gas Spammer** | Competitor or griefing agent seeking to stall consensus or exhaust contract gas. | Can submit arbitrary transactions to public EVM RPC endpoints. |
| **Plant Insider / Coordinated Falsifier** | Plant engineering staff with administrative access across multiple distinct facility operational databases. | Can simultaneously alter CEMS data and local primary fuel delivery logbooks. |

## 3. Protected Assets

| Asset ID | Asset Description | Security Objective | Impact of Compromise |
|---|---|---|---|
| **AST-01** | Gateway Private Signing Key (`d_gateway`) | Confidentiality & Integrity | Forged packets can be signed at origin, bypassing signature checks. |
| **AST-02** | Raw Off-Chain Sensor Telemetry | Confidentiality & Authenticity | Exposure leaks proprietary industrial process throughput; tampering distorts carbon accounting. |
| **AST-03** | Batch Merkle Roots (`merkleRoot`) | Integrity & Authenticity | Fake roots anchored on-chain could validate non-existent or falsified emissions batches. |
| **AST-04** | Operator & Verifier Stake Bonds | Enforceability & Conservation | Loss of economic deterrence; insolvent vaults cannot compensate honest verifiers or buyers. |
| **AST-05** | Commit-Reveal Voting Hashes | Secrecy during commit window | Front-running reveals allows lazy verifiers to free-ride without running inference. |
| **AST-06** | Period Attestation Records | Authenticity & Non-Repudiation | Corrupted attestations produce invalid CBAM reports submitted to EU authorities. |

## 4. Trust Assumptions

1. **Host Environment & Gateway Bootstrapping:** In the prototype, the edge gateway private key is simulated in software (`SoftwareSecureElement`). It is assumed that production deployments will house this key inside a dedicated hardware Secure Element (e.g., Microchip ATECC608, TPM 2.0, or secure enclave) with measured secure boot.
2. **Cryptographic Primitives:** SHA-256 and ECDSA over NIST P-256 (`secp256r1`) are computationally secure against preimage and forgery attacks.
3. **Verifier Independence:** At least 3 of the 5 verifier nodes operate independently without shared corporate control, private keys, or infrastructure collusion.
4. **Arbiter Integrity:** The dispute resolution multisig represents accredited third-party auditing bodies (e.g., EU-accredited CBAM verifiers) who act honestly when reviewing raw evidence during an overturned dispute.
5. **EVM L2 Network Liveness:** The underlying EVM L2 testnet sequencer will include valid transactions within the designated commit (1 hour) and challenge (24 hours) windows.
