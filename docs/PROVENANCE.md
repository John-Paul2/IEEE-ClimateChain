# VeriCEMS Quantitative Provenance Registry (`docs/PROVENANCE.md`)

> **Honesty & Audit Statement (`AGENTS.md` Rule 1):**  
> *"Never invent numbers, results, citations, regulation values or links. Every number in the UI or docs must come from (a) a results file generated by code in this repo, (b) a config value with a source and a last_verified date, or (c) be tagged [ILLUSTRATIVE]."*  
> 
> This document catalogs **every numerical and quantified metric** appearing across `README.md`, `docs/` (excluding the reference guide `VeriCEMS_Project_Guide.md` and `PROMPT_PACK.md`), and the user interface (`web/src/`). Each entry lists where it appears, its exact value, its provenance category, and the primary artifact from which it originates.

---

## 1. Provenance Classification Schema

| Category Tag | Definition | Permitted Verification Source |
|---|---|---|
| **`[RESULT]`** | Empirical result generated directly by deterministic code execution in this repository. | Pinned files in `results/` (`benchmark_summary.json`, `gas_measured.json`, `data_inspection.json`, etc.) or `deployments/`. |
| **`[CONFIG]`** | Fixed system parameter or regulatory input with a declared primary or secondary source and `last_verified` date. | Configuration files in `config/` or `calculator/config/` (`params.yaml`, `cbam_config.json`, `sources.json`, etc.). |
| **`[ILLUSTRATIVE]`** | Hypothetical example, walkthrough scenario, persona profile, or educational UI preset used solely to illustrate system behavior. | Explicitly tagged in code, UI labels, or documentation. |
| **`[ASSUMPTION]`** | Sensitivity variable declared transparently for climate deterrence modeling or threat analysis. | Sensitivity scenario in `config/impact_inputs.yaml` or `docs/CLIMATE_IMPACT.md`. |
| **`[NEEDS_SOURCE]`** | Primary EU regulatory constant that remains unverified from primary EU texts; stored as `null` in production code. | `calculator/config/cbam_config.json` with status `NEEDS_SOURCE`. |
